# OFFICE V3 —— 视觉重构与交互升级（P3 计划）

状态：**P3.0/P3.1/P3.3/P3.4 第一轮均已落地并通过真壳验收（2026-10-27）；代码绘制场景默认开启、跟随壳主题**
日期：2026-10-27 · 依据：用户 2026-10-27 "可以大胆更新""大肥鱼要做到像 dsh-pet""先推进到 P3 再一起深度优化视觉"

## 0. 现状与问题

- 渲染：Pixi，角色/家具全部是**图片素材叠层**；房间由已编译的 layout fixture 驱动。
- 时间：主进程 16ms 逻辑 tick → 快照推送 → 页面在快照到达时重绘（Pixi ticker 停用）。
  视觉上"一动一停"，没有连续插值；静态画面靠素材本身。
- 动效：walk 15 帧、working-back 3 帧是仅有的多帧动画；呼吸/眨眼/摆尾等"活着"的细节缺失。
- 结果：用户看到的办公室"机械、不顺眼"；角色像贴纸，不像生物。

## 1. 目标（P3 完成的定义）

1. **连续时间**：画面 60fps 插值，位置/朝向/动画相位不再随快照跳变。
2. **场景代码化**：地板、墙、家具由代码绘制（可主题化、可缩放、可程序化细节），
   不再依赖为每个道具准备贴图；保留素材作为可选风格层。
3. **角色有生命感**：至少呼吸/眨眼/摆尾/待机小动作；行走有起步-减速-停下的过渡；
   达到 dsh-pet 的"会呼吸的小生物"观感。
4. **交互**：悬停卡（已完成）→ 点击钉住 → 拖拽/摸头 → 双击派活/对话入口。
5. **可验证**：60fps（低端机 30fps 降级可接受）、无逻辑泄漏到渲染层、
   同一份快照在两种渲染模式下语义一致。

## 2. 约束（不得违反）

- **渲染层不产生事实**：所有位置/状态来自快照；插值只做呈现。
- 模拟仍在主进程：不把行为决策搬到页面（可把"插值时钟"放渲染层，但状态方程不变）。
- 主题/语言/i18n 继续走壳通道；办公室仍是投影消费者。
- 素材可替换：代码绘制与素材渲染共享同一场景描述，随时可回退。

## 3. 路线选项（需要拍板）

### 3.1 场景渲染
- **A. 全程序化**：用 Pixi Graphics 绘制地板/墙/家具（圆角、阴影、材质渐变、光照）；
  layout 描述继续作为唯一布局来源。优点：统一风格、缩放清晰、主题化、无素材债；
  缺点：需要美术方向（配色/形状语言），首批工作量大。
- **B. 混合**：环境程序化，角色保留现有鲸鱼娘素材。优点：角色形象不变、风险低；
  缺点：两种质感需要调和。
- **C. 保留素材只做动效**：最省，但"机械感"根源（贴纸叠层）仍在，不推荐。

### 3.2 角色动效
- **A. 现有帧 + 程序化动效**：插值位置/朝向 + 呼吸缩放 + 眨眼（帧/遮罩）+ 摆尾（形变/切片）
  + 待机随机小动作。优点：不需要新美术资产，最快看到"活"；缺点：表情/肢体自由度有限。
- **B. Live2D**：需要 Cubism 模型（新美术资产）与运行时；优点：表情/口型/肢体最自然；
  缺点：资产与授权成本，模型与现有形象需重做。
- **C. 自建骨骼（Spine/自定义）**：把现有帧拆件绑定；优点：介于两者之间；
  缺点：拆件与绑定工作量大，效果取决于拆件质量。

### 3.3 交互深度
- **A. dsh-pet 风**：悬停、点击钉住、拖拽（角色跟随鼠标、落地回位）、摸头反馈。
- **B. A + 任务交互**：双击角色打开该成员的任务/产物（工作坞联动）、拖到工位派活。
- **C. 仅视觉**：不动交互（与用户预期不符，不推荐）。

## 5. 技术要点（P3.0 先行）

- 快照增加 `simulatedAtMs` 与每个员工的 `facing/phase`（已有 position）；
- 渲染层保存 `prevSnapshot/currSnapshot`，按 `(now - currAt) / (currAt - prevAt)` 插值；
  朝向用最短角度插值；动画相位用 `simulatedAtMs` 连续推进（不受快照频率影响）；
- 推送到页面的频率保持现状（≤60Hz；静止 1Hz 心跳），渲染层自行补帧；
- 逻辑断点：插值只在同一 `run`/同一实体 id 之间；实体消失直接移除，不 interpolate 幽灵。

### 概念稿（临时演示，非主仓代码）

- 文件：`office-v3-concept.html`（单文件、Canvas 2D、零依赖），位置在 ZCode 可视化目录，**不在仓库内**。
- 已实现：等轴测房间（地板/两面墙/窗/踢脚线/门厅矮墙）、6 个工位（桌/显示器/椅/台灯）、厨房吧台、休息区（沙发/靠垫/矮桌/杯子/落地灯）、绿植、书架与挂钟、岛台接触阴影、窗光投影（裁剪在房间轮廓内）。
- 主题：亮/暗双主题 + 5 种强调色，即时切换；缩放随窗口自适应（`S` 自动 clamp）。
- 交互骨架：悬停高亮 + 提示、点击钉住人物卡、拖拽角色（松手回位）、角色朝向随移动方向变化；底部演示开关（空闲/工作中/走动/网格）。
- 角色：**占位形态**（蓝白胶囊体+头+尾），只用于验证比例与站位，不代表最终形象。
- 结论（待用户确认）：代码绘制可以做到"统一风格 + 可主题化 + 无素材债"，且比图片叠层更容易保证透视一致。

### 概念稿暴露的、正式落地要解决的问题

1. 角色与家具的**接地关系**（脚底阴影、桌下遮挡排序）必须在场景描述里显式声明，不能靠绘制顺序碰运气。
2. 光照要**裁剪到地面轮廓**，否则暗色主题会漏到背景上（概念稿已修）。
3. 角色尺寸/站位需要与工位尺寸绑定成参数，而不是写死坐标，否则换布局会穿模。
4. 动效缺位时，静止画面"死"得更明显——P3.2 虽暂缓，但至少要有随快照变化的姿态差异（朝向/坐姿/工作态），否则代码化收益会被观感抵消。

## 8. 实施进度（2026-10-27，代码已落地）

### 8.1 P3.0 呈现时钟（已完成，默认开启）

- `src/office/render/presentation-clock.js`：纯模块、零依赖、零 I/O。
  双缓冲最近两次快照，按 `(now - curr.at) / (curr.at - prev.at)` 在 prev→curr 之间插值；
  `alpha` 夹在 `[0,1]`，**只落后不外推**（外推等于渲染层编造主进程尚未走到的位置）。
- 断点处理：到达间隔 > `maxGapMs`（默认 250ms）、`paused:true`、`simulatedAtMs` 回退或冻结、
  实体新增/消失，一律吸附，不跨断点插值（不画幽灵）。
- 渲染器接入：`presentation` 选项（默认启用，宿主无 `requestAnimationFrame` 时自动关闭）。
  帧泵由 `interpolating()` 驱动——空闲场景**零额外帧**，下一次推送再启动；
  `setVisible(false)` / `setPresenting(false)` / `pause()` / `destroy()` 都会停泵。
- 插值的实现方式：`updateEntity` 仍按快照画在绝对坐标，帧泵用 `container.position` 平移整组节点
  （影子/占位/立绘）与效果层（选环/徽标/标记/气泡），**不重建任何 Graphics/Text**。
  `hitTest` 跟随绘制位置（`__footPx`）而不是快照位置。
- 观测量：`diagnostics().presentation = { enabled, frames, scheduled, interpolating, buffers }`。
- 测试：`test/office-presentation-clock.test.js`（10）+ `test/office-render-interpolation.test.js`（8）。
  覆盖：中点插值、收敛、无快照不漂移、超长间隔/暂停吸附、新人从自身位置出现、
  门控停泵、关闭开关回到历史行为。
- **真壳冒烟（2026-10-27，`/tmp/office-p3-smoke.js`）**：真实 Electron + 真实
  `office.html` + 生产角色包 + 5 名员工，2.5s 观测窗：
  `mode=webgl`、`presentation.enabled=true`、插值帧 150（≈60fps）、
  `paintCount` 增量 286、`buffers={prev:true,curr:true,employeeCount:5}`、
  `codeScene.enabled=false`、页面错误 0、截帧非空。判定 `P3_SMOKE_OK`。
  说明：`paintDelta` ≈ 2×推送数，是"推送时画一帧 + 插值帧再画一帧"的预期成本；
  空闲时插值泵不排帧（`interpolating=false`），不会持续耗电。

### 8.2 P3.1 场景代码化（环境已落地，预览开关，默认关闭）

**暗色修正（2026-10-27 第二轮，用户看实景截图后）**：暖棕夜色"有些奇怪"，
改为**中性灰**（冷灰底 + 冷白窗光），只靠明度层次和强调色区分；亮色窗光加强

### 8.3.1 P3.3 交互（已完成首个完整切片，2026-10-27）

已拍板的方向是 **dsh-pet + 任务联动**，其中不依赖视觉风格的部分已落地：

- **拖拽回位（渲染层）**：`beginDrag / dragTo / endDrag / isDragging / dragOffset`。
  拖拽移动的是**绘制节点**：模拟在拖拽期间继续前进，快照一个字节都不改；
  松手后 260ms `easeOutCubic` 缓动到"模拟当前所在位置"，而不是用户放下的位置
  （避免松手瞬间跳回原位）。没有呈现时钟时（无 rAF）直接吸附。
  命中测试跟随绘制位置（`__footPx`），所以拖到哪里都能再次抓住。
- **页面手势**：4px 阈值区分"点击钉住"与"拖拽"；拖拽后吞掉随之而来的那一次
  click（不会误触发选中/钉住）；拖拽期间收起悬停卡并释放 present 冻结。
- **双击联动工作坞**：双击角色 → `bridge.focusMember(employeeId)` →
  壳自有通道 `shell:office-focus`（**office:* 仍是冻结的 8 个**）→
