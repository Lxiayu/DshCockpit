## 1. 为什么考虑换投影

现状是**平面正交 + 竖直拉伸**：房间是俯视图，家具是"顶面 + 前立面"的伪 3D 盒体。
它能做体积，但做不出概念稿那种"站在房间里看"的空间感，原因不是细节不够，而是：

- 平面投影里所有物体的"远"只靠 y 坐标表达，没有高度方向的透视收敛；
- 家具只能看到顶面和一个前立面，侧面与遮挡关系永远读不出来；
- 角色的海报化立绘与"顶面房间"本来就不是同一套透视。

结论：继续在平面里堆细节，收益递减；真正的跃迁是等轴测（2:1 dimetric）。
代价是投影、遮挡、命中测试、角色朝向全部要重做——所以先立项、先评审。

## 2. 目标与非目标

**目标（I4 完成时的验收）**

1. 房间、家具、角色在同一套等轴测投影里，视觉上像"一个房间"，而不是"地图 + 立绘"。
2. 6 个工位与座位锚点对齐：角色落座时落在椅子上、面对桌子（或背对观众，与原设定一致）。
3. 遮挡正确：角色被桌子前沿/椅背遮挡的部分与当前语义一致；走动时前后关系正确。
4. 交互不退化：悬停钉住、拖拽回位、双击定位工作坞、命中测试全部可用。
5. 60fps；主题（亮/暗）切换；`?projection=flat` 可回退到当前外观。

**非目标**

- 不改模拟：移动图、座位锚点、reservation、Team facts 一律不动。
- 不改通道：`office:*` 仍是 8 个，`shell:*` 不新增（除非交互需要）。
- 不引入 3D 引擎（Three.js 等）：仍是 2D Canvas/Pixi，等轴测只是投影函数。
- 不做自由旋转视角（固定 2:1 等轴测）。

## 3. 视觉规格

- **投影**：2:1 dimetric（像素风等轴测）。`sx = (x - y) * cos30 * S`、
  `sy = (x + y) * sin30 * S - z * S`，其中 `cos30 ≈ 0.866`、`sin30 = 0.5`；
  为像素对齐可用 2:1 近似（`cos=1, sin=0.5`），与概念稿一致。
- **房间**：地板菱形网格 + 两面墙（后墙、左墙）+ 窗（后墙右段）+ 踢脚线；
  墙上挂钟、书架；左侧弱化前台（矮台面 + 地面分色）。
- **家具**：桌（桌面 + 桌腿 + 挡板 + 显示器 + 键鼠 + 纸张/笔筒）、椅（背/座/五星脚）、
  休闲区（沙发/茶几/地毯/落地灯）、茶水间（吧台/水槽/咖啡机/冰箱）、绿植。
  全部由 `code-office` 的布局规则生成世界坐标（footprint + height），投影层负责落屏。
- **光照**：固定方向（左上），地面投影 + 窗光池；暗色中性灰（用户已拍板），
  不做暖棕。
- **角色**：保持现有立绘（不重画），作为 billboard 立在投影后的落点上。

## 4. 技术设计

### 4.1 新增投影层（纯函数）

`src/office/render/iso-projection.js`：

- `project(point, camera) -> {x, y}`：世界 `(x, y, z)` → 屏幕（CSS px）。
- `unproject(screen, camera, z=0) -> {x, y}`：屏幕 → 地面平面（命中测试用）。
- `camera`：`{ originX, originY, scale, tile }`，随窗口尺寸计算（保持场景居中、
  留出右栏工作坞的空间）。
- 纯函数、零依赖、可单测：往返投影误差 < 1e-6。

### 4.2 场景描述

沿用 `code-office.js` 的世界坐标（桌/椅/显示器/休闲区/茶水间/绿植），
新增 `z`（离地高度）与 `height`。渲染器把它投影成多边形：

- 顶面：4 个角 `(x, y, z+h)`；
- 正面：底边 `(x, y, 0)..(x+w, y, 0)` 与顶边 `z+h`；
- 侧面：同理由深度轴展开。

排序键统一为 `x + y + z * 0.001`（画家算法），同类同键按 id 稳定排序。

### 4.3 遮挡

- 单层 painter's algorithm：所有可见对象（家具部件、角色、气泡/徽标）进同一个
  排序列表，按深度键从远到近绘制。
- 桌子的"前沿遮挡角色下半身"不再靠图层技巧，而靠深度：角色脚点 `x+y` 小于
  桌面前沿的 `x+y` 时，桌子自然画在角色上面。
- 地面/墙/窗固定在最底层；徽标/气泡在最顶层（交互覆盖层不参与遮挡）。

### 4.4 命中测试与拖拽

- 命中：`unproject(pointer, z=0)` 得到地面点；按角色 footprint 半径（投影后的椭圆）
  选取最近者；家具不需要命中。
- 拖拽：屏幕像素偏移直接加到绘制位置（与现在的 `dragOffset` 语义一致），
  不参与投影/反投影；松手缓动回投影后的落点。
- 悬停冻结、presenting、双击定位保持现有逻辑（都是屏幕空间）。

### 4.5 角色立绘的等轴测读法

- 立绘保持 billboard：脚点锚定在 `project(seat)`，不旋转、不缩放透视。
- 四方向：`down/up/left/right` 仍用现有帧；等轴测下"斜向移动"没有对应帧，
  方案 A 复用最近方向（现状也能接受）；方案 B 以后补 8 向美术（新资产，另立项）。
- 坐姿朝向：现有 `presentation.facing='back'` 的语义不变（背对观众）。

### 4.6 与事实边界

- 投影层只读快照 + 布局，不产生事实；不加 IPC、不改通道。
- `presentation-clock` 的插值在世界坐标里做，投影在绘制时应用（顺序：插值 → 投影）。
- 主题调色板沿用 `code-scene.js`；等轴测只新增 `wall/floor` 多边形，不新增色板。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 立绘与等轴测透视不匹配（贴纸感） | 先做 I1 灰度截图，用户确认后再做家具；必要时补 8 向/斜向美术（另立项） |
| 遮挡排序在密集家具处闪烁 | 深度键加稳定 tie-break；同类部件合并；每帧只重排变化项 |
| 座位对齐误差 | 以 `seat` 世界坐标反推桌/椅 footprint，单测断言"脚点落在椅面内" |
| 命中测试偏移 | 反投影用同一 camera；单测 `project(unproject(p))≈p`；真壳点击验证 |
| 性能 | 6 角色 + ~80 部件，2D 多边形绘制；插值仍是屏幕空间；静态零重绘 |
| 回退成本 | `projection=flat` 保留现有渲染路径，不删代码 |

## 7. 需要拍板的问题

1. **房间形态**：开放办公区（无墙、只有地板分区）还是带两面墙的"房间"？
   概念稿是后者，视觉更强，但会遮住部分工位。
2. **角色美术**：先用现有四向立绘（贴纸感可接受）还是同时立项 8 向/斜向美术？
3. **家具密度**：6 工位 + 休闲/茶水（当前规则）是否够，还是需要更多道具（书架、白板、隔断）？
4. **默认切换时机**：I3 验收后立即默认，还是先灰度一个版本？
