## 1. 先解决一个矛盾：P4 清单与设计文档冲突

路线图 §P4 列了「更多办公室交互物件（会议桌 / 资料架 / 成果区）」。
但 `docs/design/office-interaction.md` 已经逐条判过：

| 物件 | 设计文档结论 | 理由 |
|---|---|---|
| 会议桌 | **不做** | 没有"会议"这个事实源；提出不了有事实后果的操作 |
| 资料架 | **不做** | 本仓没有知识库事实源 |
| 成果区 | **不做物件** | 会与工作坞重复；正确做法是"角色桌面随产物增加"的微表现 |

**结论：P4 清单里"更多物件"这一项应该砍掉，不是做。**

如果照路线图做会议桌，会做出一个**装饰性谎言**——这正是本项目
`product-principles.md` 明令禁止的（"UI 不编造状态"）。

## 2. 那 P4 到底该做什么

先问：**现在用户最不满意的地方是什么？**

不做主观猜测，用**已有的证据**推断：

### 证据 1：Mission Desk 的空状态

从真机验收截图看，第一次打开 Desk 时看到的是：
```
边界：未声明边界。
决策（含理由）：还没有记录决策。
未决问题：没有未决问题。
工作流：还没有工作流。
产物：还没有登记产物。
```
**五个"还没有"。** 新用户打开会不知道从哪开始。

### 证据 2：Companion 只有数字

Companion 小窗显示"3 件待你处理"，但**点开之前不知道是什么事**。
用户需要的是"够不够我决定是否现在处理"，不是"有多少件"。

### 证据 3：错误提示的粒度

多处失败提示是 `失败：${code}`（例如 `DESK_UNAVAILABLE`）。
对开发者有用，对用户是噪音。

## 3. 第一性原理：体验打磨的本质是什么

不是"做得更漂亮"。是**减少用户想放弃的时刻**。

用户放弃一个工具通常发生在三个时刻：
1. **第一次打开，不知道从哪开始** → 空状态问题
2. **看到一个提示，但不知道它要什么** → 错误粒度问题
3. **感觉不到进展** → 反馈缺失问题

所以 P4 的优先级应该是：**空状态 > 错误粒度 > 反馈**。
而"更多物件"不在这个列表里——因为还没有用户抱怨缺物件。

## 4. 本轮做什么

| 步 | 内容 | 为什么排这个优先级 |
|---|---|---|
| **S1** | Mission Desk 空状态引导 | 第一次打开就是五个"还没有"，是最强的放弃信号 |
| **S2** | 错误提示可读化 | 用户看到 code 不知道怎么办 |
| **S3** | 真机验收 | 空状态与错误提示都只有真机能验 |

**不做**：更多物件（设计文档已判不做）、Live2D（Deferred）、
第二个 Capability Pack（没有第二个真实需求）。

## 5. S1 设计：空状态不是"占位文案"

空状态的设计原则（这是 S1 的核心判断）：

| ❌ 错的做法 | ✅ 对的做法 |
|---|---|
| 显示"暂无数据" | **告诉用户下一步做什么** |
| 一次性显示所有提示 | **只提示最关键的那一个动作** |
| 用虚构数据填充 | **保持空白，但给出路标** |

具体到 Mission Desk：五个区块都有空状态，但**用户不该同时看到五个提示**。
正确做法是：**只在真正"空"且"该有内容"的地方给引导**，
并且第一个动作要指向"创建 Mission"（如果连 Mission 都没有）。

所以实现上要分两层：
- **Mission 列表为空** → 引导创建（这是根节点）
- **某个区块为空** → 一句话说明这个区块是干什么的 + 一个具体动作

## 6. S2 设计：错误提示的分级

不是所有错误都该"人话化"。分两类：

| 类型 | 处理 |
|---|---|
| **用户能处理的** | 给可执行建议（"文件不存在，请检查路径"） |
| **用户不能处理的** | 给一句人话 + 保留 code 供反馈（"操作失败（代码 DESK_UNAVAILABLE），请反馈"） |

关键是**不能丢掉 code**——那是排查的唯一线索。做法是
「人话 + 括号里的代码」，而不是二选一。

## 7. 验收标准

- [ ] 零 Mission 时，Desk 显示明确的创建引导（不是五个"还没有"）
- [ ] 有 Mission 但区块为空时，每个区块一句话说明用途
- [ ] 至少 3 处错误提示变成「人话 + code」
- [ ] 真机验收：能截图证明空状态的视觉效果
- [ ] 不引入虚构数据（空就是空，但不能是死路）

## 8. 非目标

- ❌ 更多办公室物件（设计文档已判不做）
- ❌ Live2D / LayerFS / Knowledge（Deferred）
- ❌ 改 Mission Desk 的信息架构（只改空状态与提示）
