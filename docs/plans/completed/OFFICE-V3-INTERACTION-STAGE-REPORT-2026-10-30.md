## 2. 修好的真实缺陷（每条都有可复现证据）

### 2.1 办公室模拟永久冻结（"从来不聊天"的真因）
三个可见性上报缺陷叠加：window-manager 去重早于 `isVisible()` 判断、
页面加载时不上报初始可见、blur 被当成 hidden。三者导致 `visibleViews` 恒为空
→ `isPaused()` 恒真 → 整个仿真不 tick。证据：`ticks=0` vs 修复后 `ticks=3492`。

### 2.2 坐姿素材错位
`seatedAtWorkstation` 把"有任务意图"当成"已就座"。改为用 `rec.reachedSeat` 判断。
验证：0/15000 坏帧。

### 2.3 气泡文字跑到画布左上角
`placeEntity` 对 effects 层节点写绝对坐标，而插值偏移（驻留时为 0,0）覆盖了它。
改为记录 `record.__effectsOffset`，在 `updateEntity` 里叠加。

### 2.4 聊完天角色永久卡死
死锁环：coder 停在 chat-b 想走 roam-3，researcher 停在 roam-3 想去 chat-b。
根因是 `endChat` 只清了调度器预留，没清模块侧 `parkReservation`。
修复后最长非聊天停滞 30s+ → 7.0s。

### 2.5 拖拽松手弹回原位（两个独立缺陷）
1. `office:place` 只加了 preload 白名单和校验器，**漏了 `OFFICE_IPC_CHANNELS`
   与 `registerOfficeIpc` 的 switch** → 落到 `CHANNEL_UNKNOWN`，位置从未写回
2. **CSS 像素当 scene 像素用**：窗口 1280×840 / 参考 960×630 差 1.333 倍，
   落点放大 33%，吸附到错误节点

### 2.6 交互区只有脚下圆形
改为角色立绘的真实身体矩形（宽度由纹理长宽比推出、收窄到 55%）。
真机验证：头/中/脚三点命中，边界外全 miss。

## 3. 回退的方向性错误

### 3.1 左右站位闲聊（整体撤掉）
用户原话："现在的左右交流这块确实很烂……进行一次大的回退。"

横向座位对只能落在两列办公桌之间的窄过道（约 84px，两侧是工位家具），
两人并排时各自朝外看，比背对背更抽象。三条补救全不成立：

| 尝试 | 结果 |
|---|---|
| 运行时空间检测自动退回 | 生效，但等于这对座位永远用不上 |
| 页面最下方 (370,570) | 离 roam-8 仅 65px，被判空间不足 |
| 右侧走廊 (700,480) | 余量 267px 最优，但占掉 roam-11 理想位置 → `GRAPH_BLOCKED` |

**结论性规则**：一个视觉特性如果三种合理解法都只能得到"更糟"的结果，
问题在方向本身，应撤掉而不是继续调参。

### 3.2 顺带修掉的哈希 bug
座位对选择用的朴素 FNV（`(h ^ c) * 0x01000193`）在 JS 双精度下低位几乎恒定，
实测所有配对都命中第 0 组。改用 `Math.imul` + `>>> 0` 后分布正常。
（此代码随回退一起移除，但教训保留：**JS 里做 32 位哈希必须用 Math.imul**。）

### 4.1 「鱼片」查证结论（值得记住的方法论）
用户直觉是对的，但理由比"觉得奇怪"更硬：

| 维度 | 结论 |
|---|---|
| 有无出处 | **有**。2026-08 起模型在 `PERSONA_LOAD` 人格下会自发生成，多家媒体报道 |
| 是否社区共识 | **不是**。萌娘百科词条全文 0 次；主流 GitHub 人设仓库无一使用 |
| 社区语义 | 1394 条梗图中仅 4 次，全是「生鱼片/刺身」双关（=把她切片） |
| **场景是否成立** | **不成立**。这是她对**人类用户**的称呼，而我们是鲸鱼娘**互相**闲聊 |

最硬的理由是场景，不是出处。已删除并固化为测试。

## 6. 留下的规则

1. **跨进程功能必须端到端验证。** "组件返回了正确值" ≠ "链路通了"。
   拖拽这个功能曾报了"已修复"但实际没通，因为只测了 `endDrag()` 返回值。
2. **JS 32 位哈希用 `Math.imul`。** 朴素写法低位恒定，选择类逻辑会退化成"永远选第一个"。
3. **视觉收益为负就撤，别调参。** 左右站位是典型案例。
4. **删内容前先查证出处与场景，两个维度都要过。** 「鱼片」有出处但场景不成立。
5. **gate 要机械化。** 语料红线写成测试，不靠人记。
