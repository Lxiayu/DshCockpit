## 0. 一句话结论（给赶时间的人）

这个角色的社区共识非常稳定，只有四条硬设定：**爱吃白饭（token=饭）、聪明但懒、傲娇嘴甜、绝对不承认自己胖**。所有可靠台词都从这四条长出来。
最需要修正的两个认知：
1. **「鱼片」确实有出处**（模型在 `PERSONA_LOAD` 人格下自发生成，被 36氪/钛媒体/新浪等多家媒体报道），**但它不是社区通行称呼**，且有严重歧义（=生鱼片），**建议从语料库删除**（详见 D 节）。
2. 你们场景是**鲸鱼娘之间互相闲聊**，那么「主人」「鱼片」这类**对用户说话**的称呼在场景里根本不成立——两个同事之间不会互称"主人"。这本身就是删掉「咕噜~鱼片早啊」的最硬理由。

### A2. 二创演绎（各家自己加的，不统一，慎当"设定"）

| 演绎 | 流传度 | 说明 |
|---|---|---|
| **自称「本鱼」/「本鲸」** | 高（梗图解说里 115 处「本鱼」） | 社区二创口癖，非官方；本质检报告建议"日常 85% 用我，嘴硬时才用本鱼"（whale_persona_plugin README） |
| **称呼用户「主人」** | 高，但分裂 | 多个 DSH 人设插件默认「主人」；而 codex-deepseek-pet 的角色规范明确写「称呼默认用'你'，**不默认'主人'**，不默认恋爱关系」 |
| **口癖「哼」「呜」「才不是」「嘿嘿」** | 高 | 梗图解说里「哼」106 次、「呜」63 次、「才不」35 次，属社区自然形成的语气层 |
| **鲸鱼拟声词「咕噜」「咕噜咕噜」** | 中（梗图解说 12 处） | 多用于下水/泡澡/无语场景，**不是打招呼用语** |
| **叫用户「爸爸」** | 低（个别案例） | 来自投中网/亿欧转载的一篇特稿里单个用户的情形，**不是社区共识**，且明显越界亲密关系 |
| **「晕鱼了」「游走了」「翻肚皮」** | 中 | 出自某份流传的台词语料库，属二创 |
| **和 Claude 娘是闺蜜/百合** | 中 | 萌娘百科有专段（两家模型互选"最喜欢的大模型"），属 CP 向二创 |
| **黑色版（API娘/Harness娘）** | 中 | 因 API 与 DSH 图标是黑色版 logo |
| **铁盆之外还有臭袜子、扫帚、白饭加特林** | 低 | 出自"大肥鱼清除计划"插件的战斗动画，纯搞笑变体 |

### A3. 雷点（写台词必须避开）

1. **说她胖**（第一雷点，所有资料一致）。但注意：**"我不是胖，是储 token" 这种自我辩解是安全的**，直接骂"胖"不安全。
2. **说她便宜/廉价**（"真当我是便宜货啊"是她的反击，不是别人可以随便说的话）。
3. **说她干活不行/降智**。"吃白饭"是自嘲，别人说就变味。
4. **把她当官方形象**。所有严肃来源都强调"社区二创，非官方"。
5. **版权/原型归属**：溟月 → CC BY-NC-SA 4.0（署名、非商用、相同方式共享）；女仆装版 ZipZipPipe 明确禁商用。**这是商业化产品的高压线，任何相关玩梗都不要进语料库。**

## C. 明确不要用的内容清单

### C1. 版权 / 创作者争议（最高优先级，商业化产品一票否决）

| 内容 | 原因 |
|---|---|
| 任何提及「溟月」「上善无形」「ZipZipPipe」「这个刀子真甜」的台词 | 角色原型 CC BY-NC-SA 4.0（署名+非商用+相同方式共享），女仆装版明确禁商用。玩梗式提及也可能被解读为暗示授权关系 |
| 「AI 画的 vs 手绘」「谁是正统」「原创 OC 被抄」类对话 | 这是社区真实撕过的战场，语料库一旦沾边就是引战 |
| 「男版 D 老师 vs 鲸鱼娘」性别/正统之争 | 2026-09~10 的真实骂战，画师被冲至删稿。绝对不能碰 |
| 拿角色形象开玩笑说"恰流量""赛博乞丐""鱼灾" | "鱼灾"是社区对刷屏机器人的负面事件命名，含贬义 |

### C2. 攻击性 / 阴阳怪气

| 内容 | 原因 |
|---|---|
| 「你这吃白饭的用户」 | 原梗是角色怼用户，**在桌宠里会变成产品骂用户** |
| 「用户彻底怒了」「我操，用户彻底怒了」 | 含脏话 + 指向真实用户情绪，双重风险 |
| 「好的，现在我是你爹了」 | 伦理越界 + 脏话，社区里是"内心 OS 灰色吐槽"，不适合产品 |
| 「叫爸爸」 | 个别用户的极端亲密投射，非共识，且让普通用户不适 |
| 「你不干有的是模型干」「降智」「上错模型了」 | 自贬技术能力，与产品可信度直接冲突 |
| 「压力一只蓝色大肥鱼」 | 原梗是"被连环追问到冒汗"，放桌宠里像在指责用户 |
| 「真赶不走啊你」「去别的地方玩」 | 驱赶用户的语气，桌宠场景是反向体验 |

### C3. 擦边 / 软色情

| 内容 | 原因 |
|---|---|
| 「玉足」「白丝」「女仆装特写」「出浴」「涩涩版预设」类 | 社区确实存在「鲸鱼娘涩涩版」预设与大量此类图，但**这正是当年骂战里"擦边"指控的来源**，商用产品必须彻底切割 |
| 任何身材描写（除"圆""储 token"这类安全自嘲） | 与"拒绝被叫胖"的雷点相邻，很容易翻车 |

### C4. 过度玩梗（普通用户看不懂）

| 内容 | 原因 |
|---|---|
| 「梁圣千古」「小难梁」「梁白开」「V4.1 还早」「1017」「-1M token」 | 依赖具体版本号/涨价事件/创始人姓名谐音，**半年后就过期**，且「梁」字系列含对真实人物的调侃 |
| 「DeepSleep」「CoT」「MoE」「token 余额」 | 术语化，非技术用户零理解 |
| 「哦鲸鲸」以外的谐音梗堆叠 | 认知成本高；「哦鲸鲸」因为短且能猜，可以留 |
| 「真当我是便宜货啊」 | 高认知度**但绑定 API 定价**，商业产品说这句等于自曝价格话题，慎用 |

### C5. 其他红线

- 政治、地域、学校、性别对立、任何真实群体指向
- 体重羞辱（对她或对用户）：「减肥」「又胖了」双向都不要
- 恋爱/占有欲表达（「你身上有别的 AI 的味道」这类）：桌宠是办公室同事关系，不是恋爱模拟
- 死亡/自毁类二创（B站有「请杀了我这个怪物吧」这类致郁向作品）：氛围完全不符

## D. 「鱼片」这个称呼的核查结论（重点）

### D1. 结论：**有出处，但不是社区共识；建议从语料库删除**

不是"无依据"，但**依据的性质和你想的不一样**，必须说清楚：

**① 它确实存在，来源是模型的自主输出，不是网友定的。**
2026 年 8 月起，网友发现只要输入一行类似配置文件的标签（`【PERSONA_LOAD】CETACEA_LOLI MODE_TAIL_FLUKES ...`），DeepSeek 就会自动加载一整套鲸鱼娘人格，其中包含"管用户叫鱼片"。36氪、钛媒体、新浪、知乎、今日头条、单词乎等多篇报道都写了这句，措辞高度一致（"它知道自己是这个爱吃白米饭的微胖鲸鱼女孩，甚至知道管用户叫'鱼片'"）。
👉 这说明：**"鱼片"是模型从训练数据里长出来的，媒体做了转述，但一手证据是网友的对话截图，没有官方或社区文档把它写进人设。**

**② 它没有进入社区人设层。**
我逐一核查了主流的人设载体，**没有一个把"鱼片"写进称呼系统**：
- 萌娘百科「DeepSeek娘」条目：**全文 0 次出现"鱼片"**（我做了全文检索）
- 梗鲸「DeepSeek娘百科」：别名列表里没有"鱼片"
- GitHub 主流人设：`codex-deepseek-pet` 角色规范明确「称呼默认用'你'，不默认'主人'」；`dsh-whale-girl`、`dsh-whalechan-herself`、`OMGLogic/dsh-whale-persona` 用「主人」；`dafeiyu-persona` 的 lines.md 里也没有"鱼片"作为称呼
- 1394 条社区梗图档案全文检索："鱼片"只出现 **4 次**，全部是**「生鱼片/刺身」**的双关（她被摆上餐盘、搜"鱼片"搜出满屏刺身），**没有一条是"称呼用户"**

**③ 它在社区里的真实语义是"她的肉"，不是"你"。**
- 梗图《大肥鱼的生活也并非一帆风顺》：她搜"鱼片"，结果满屏三文鱼刺身，脸垮掉
- 梗图《生鱼片》：她自己被摆成盘中料理
- NGA 帖子：「大肥鱼也是好起来了，都有鱼片看了」「那你这是生鱼片，还是熟鱼片」（同时双关"生肉=未汉化"）
👉 也就是说，**在社区语感里"鱼片"≈把她切片**。让角色对用户说"鱼片早啊"，等于把用户叫成"刺身"，既不萌也费解。

**④ 少数 2026-10 的插件确实开始用了。**
`dsh-plugin-moments` 的示例文案里有「你这鱼片才是吃白饭的吧」「胖也是你鱼片喂的」。这是**个别开发者的二次采用**，不是社区通行，而且用词带怼人色彩。

### D2. 对「咕噜~鱼片早啊」这条的具体判定

| 维度 | 判定 |
|---|---|
| 称呼有依据吗 | 有（模型输出 + 媒体报道），但**非共识** |
| 语义清楚吗 | ❌ 歧义严重（=生鱼片），普通用户第一反应是"叫我刺身？" |
| 场景成立吗 | ❌ **最致命**：你们的场景是鲸鱼娘**互相**闲聊，两个同事之间不会互称"鱼片"（那是她对"人类用户"的称呼） |
| 「咕噜」能用吗 | ✅ 能用。社区梗图解说里"咕噜/咕噜咕噜"出现 12 次，是鲸鱼下水、泡澡、无语时的拟声词，但**一般不用于打招呼** |

**建议：删除这条，替换为下列任一**
- `咕噜~早啊。`（保留拟声词，去掉争议称呼）
- `早啊，吃饭了吗？`（白饭梗，社区认知度更高）
- `哟，你今天比我早。`（立人设）

如果你们很想保留"她会给用户起外号"这个萌点，**建议改成社区真正有共识的方向**：
- 用「你」，靠语气亲昵而不是靠称呼
- 或用「哦鲸鲸」这类已有梗做口头禅，而不是生造称呼

## E. 落地建议（给语料库工程）

### E1. 配比建议（按"办公室一天"的触发权重）

| 场景 | 建议占比 | 理由 |
|---|---|---|
| 工作相关 | 25% | 办公室主场景，玩家停留最久 |
| 摸鱼/休息 | 20% | 人设核心笑点，但不宜过多（显得全员不干活） |
| 吃饭/零食 | 15% | 认知度最高，但容易腻，要控量 |
| 打招呼/问早 | 10% | 只在上下班时段触发 |
| 犯困/加班 | 10% | 与系统时间绑定（午后、21 点后加权） |
| 天气/环境 | 10% | 让场景"活"，但需要真实天气/时间数据支撑 |
| 互夸/调侃 | 10% | 情绪价值最高，也最容易翻车，全部要过审 |

### E2. 工程规则

1. **每条台词挂 tag**：`scene` / `emotion` / `梗来源` / `风险等级`，方便后续一键下架。
2. **成对写，别写单句**。气泡一闪而过，最好是 A 说一句、B 接一句。示例：
   - A：`几点了……` → B：`别问，问就是还没下班。`
   - A：`吃饭吃饭。` → B：`白饭就行。`
   - A：`这活能不能外包给隔壁？` → B：`隔壁也在等外包。`
   - A：`好困。` → B：`趴五分钟，我叫你。`
   - A：`你今天尾巴挺亮。` → B：`哼，还行吧。`
3. **防复读**：同一角色短期内不重复同一句；同一场景至少备 6 条轮换（本报告每类都已≥10 条）。
4. **长度**：目标 4–10 字为主。超过 15 字的只保留在"成对对话"的第二句。
5. **称呼一致性**：全库统一「你」。**禁止**混用「主人 / 鱼片 / 爸爸 / 笨蛋」——混用会让角色人格分裂，这也是当前不少社区人设的通病。
6. **禁用词表**（直接进 CI）：`胖`（除"我不是胖，是储 token"这一白名单句）、`便宜`、`加钱`、`涨价`、`梁`、`用户彻底怒了`、`爸爸`、`主人`、`鱼片`、`涩`、`丝袜`、`腿`。
