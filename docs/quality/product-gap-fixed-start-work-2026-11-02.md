> 日期：2026-11-02

> 并质问"50 轮对话到底做了什么？"

## 0. 承认问题的严重性

用户说得对。我查证后确认：

**29 个 Mission action 里，0 个能让 Agent 开始工作。**

全部是 `list/get/create/record*/update*/link*` —— 记录、查询、关联。
所以用户创建 Mission 后，**除了填表单，真的没有下一步**。

### 更严重的是我之前的判断错了

我在文档里写过：

> "委托任务给 Lead 需要 API，grep `team/spawn` → 0"

**这个推理漏了一步。** `session/prompt` 就是那个 API——
我们**已经在用**它（Brief 验证探针里就是 `session/prompt` 让模型回答问题），
`harness-rpc.js:383` 也早就实现了 `prompt()`。

**我只是没把它接到 Mission 上。**

## 1. 修了什么

### 1.1 新增 `startWork` action（核心）

```js
startWork({ missionId, task }) →
  1. 拿（或创建）这个 Mission 的 Harness 会话
  2. 把「任务 + Mission 目标/约束」通过 session/prompt 发过去
  3. 绑定 sessionId 到 Mission（存本机，不进事件日志）
  4. 记一条 TaskRef，让 Mission 知道"有一次执行发生了"
```

**为什么把目标一起发**：Agent 在新会话里是失忆的。
AGENTS.md 的 Brief 只在**会话启动时**被读；已存在的会话不会重读。

### 1.2 会话绑定存哪儿

存 `<workspace>/.dsh/mission-sessions.json`（0600 + 原子写）。

**为什么不存进 Mission 事件日志**：
和 `lastSeenAtMs` 同理——这是**本机的执行绑定**，不是项目事实。
写进事件日志会跟着项目同步给别人，而对别人毫无意义。

### 1.3 UI：「交给团队」区块

放在详情区**最顶部**（不是底部），因为它是"下一步做什么"的答案，
不该藏在十几屏表单之后。

```
┌────────────────────────────────────────┐
│ 交给团队                                │
│ 告诉团队这个 Mission 要做什么。          │
│ 会新开一个 Harness 会话，并把目标带过去。 │
│ ┌────────────────────────────────────┐ │
│ │ 例如：先调研 Agent Team 的前沿方案… │ │
│ └────────────────────────────────────┘ │
│ [交给团队]                              │
│ ────────────────────────────────────── │
│ 在 Harness 中查看这个 Mission 的执行 →  │
└────────────────────────────────────────┘
```

用强调色（紫）边框，视觉上明显区别于其它"参考资料"区块。

## 2. 真机验收抓到的真实 bug

**第一版**：先显示"已交给团队"，再 `loadDetail()` 刷新。

**问题**：`loadDetail()` 重建整个详情区 DOM，**把刚写的成功提示冲掉了**。

**结果**：工作真的发出去了，但**界面看起来毫无反应**——
正是用户抱怨的那个症状。

**修**：先刷新，**刷新后重新拿节点**再写提示。

> 这个 bug 如果不做真机验收根本发现不了：
> 离线测只能证明"调用了 startWork"，证明不了"用户看到了反馈"。

## 6. 这解决了什么，没解决什么

### 解决了

- ✅ 创建 Mission 后**有明确的下一步**
- ✅ 输入一句话就能把工作发给 Agent
- ✅ 目标/约束会自动带上（Agent 知道在做哪个项目）
- ✅ 发出去后有明确反馈 + 去哪儿看

### 没解决（下一步）

| 问题 | 说明 |
|---|---|
| Agent 完成后**不会自动回写 Mission** | 需要监听会话完成事件 |
| Harness 视图里**看不到 Mission 名字** | 需要通过 Brief 或其它方式关联 |
| 一个 Mission **只能绑一个会话** | 长期项目可能需要多个 |
| 用户**无法在 Desk 里看到 Agent 的回复** | 需要跳 Harness 视图（这是有意为之，避免做第二个聊天框） |

## 7. 回答用户的质问

你问"50 轮到底做了什么"。

**诚实回答**：前三件事做了，第四件缺了。

| # | 做了什么 | 用户能感知吗 |
|---|---|---|
| 1 | **让产品不坏**（修 bug/假✅/安全/升级/门禁） | 间接 |
| 2 | **让产品能记录**（Mission/决策/发现/产物/待办） | ✅ |
| 3 | **让产品能观察**（团队任务/plan-review/结构化选项） | 部分 |
| 4 | **让产品能工作**（交给团队） | ❌ **之前完全缺失，现在补上** |

**这是我的排序错误**：第 2 件做完后应该立刻做第 4 件，
而不是继续打磨"观察"和"记录"。
