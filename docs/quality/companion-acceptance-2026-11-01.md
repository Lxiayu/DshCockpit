## 1. 先澄清：rail ≠ Companion

路线图「关键文件」写的是 `office-rail.js` 扩展。核实后发现两者是不同东西：

| | 现有 `office-rail.html`（186 行） | Companion 要的 |
|---|---|---|
| 形态 | 主窗口内的**左侧竖条** | **桌面常驻小窗** |
| 职责 | 视图切换器（harness/work/office 三个 tab） | 把办公室收成一个可随时唤起的小窗 |
| 生命周期 | 跟随主窗口（`addChildView`） | **主窗口关闭后仍存在** |

所以不是"给 rail 加个按钮"，而是**新建一种窗口形态**。

## 2. 第一性原理：小窗该显示什么

用户在**不打开完整办公室**时，只关心一件事：**「有没有需要我处理的事」**。

推导链：

1. 不打开完整窗口 → 注意力在别处
2. 注意力在别处 → 只可能被**值得打断**的信息吸引
3. 值得打断的只有两类：**待你处理**（阻塞进展）与**任务在跑**（让人安心）
4. 其余（谁在走动、今天用量、Mission 全貌）都不值得打断

所以派生层只输出两个数字 + 一个布尔。**这也决定了"不丢状态"的含义**：
不是"小窗能看到所有状态"（那会让 PixiJS 常驻），而是"小窗如实反映那两个
决定性数字，且展开后完整状态还在"。

## 3. 三个设计决定

### 3.1 独立 BrowserWindow，不是子视图

验收标准要求"主窗口收起后仍在"。子视图（`WebContentsView`）随主窗口销毁，
做不到。代价是多一个渲染进程，但它加载的是极简页面（一个点 + 一行字）。

### 3.2 collapsed 不加载 PixiJS

常驻窗口加载完整办公室 = PixiJS 常驻 = 成本不可接受。
小窗只显示数字，想看画面就展开。

### 3.3 数据复用 `office:state`，不新建通道

`pending` 与 `employees` 已在快照里，派生是纯函数（`companion-state.js`）。
新建数据源会造成"两处各自算"——迟早不一致。

## 4. 产品纪律：0 待办绝不亮红

一个永远亮红点的常驻图标，用户两天内就学会无视它——那时真正的告警
也就失效了。所以 `hasAttention` 是**显式的**，0 时必须为 false。

真机实测（`getComputedStyle` 读实际生效颜色，不是查 class）：

| 状态 | 颜色 | 文案 |
|---|---|---|
| needs-you | `rgb(255, 92, 92)` 红 | `3 件待你处理` + 数字 |
| idle | `rgb(74, 222, 128)` 绿 | `空闲中`（**隐藏数字**） |
| working | `rgb(255, 207, 122)` 琥珀 | `2 个任务运行中` |
| disconnected | `rgb(107, 114, 128)` 灰 | `未连接` |

## 5. preload 极简

常驻窗口的每个 API 都是**长期**攻击面。只暴露 4 个（含 1 个只读缓存 getter）：

| 方法 | 用途 |
|---|---|
| `onState(cb)` | 接收已派生的状态（数字，无正文） |
| `onLanguage(cb)` | 跟随语言切换 |
| `lastState()` | 只读缓存（语言切换时重绘，避免闪烁） |
| `expand()` | 展开完整办公室（**唯一**的写语义，且只是"开窗口"） |

**拿不到**：`office:dispatch` / `office:pending` / `mission:*` / `settings:*`。
常驻挂件不需要那些能力，给了就是多余的风险。

## 7. 「不丢状态」的三层含义与实现

路线图的验收标准是「把办公室收成常驻小窗，**不丢状态**」。实现上分三层：

| 层 | 含义 | 由谁保证 |
|---|---|---|
| 1 | 窗口切换不重建渲染器（不丢摄像机/选中/滚动） | 展开 = 显示已有主窗口，不重建 |
| 2 | 主窗口关闭后 Companion 仍在 | 独立 BrowserWindow |
| 3 | 数据不因形态变化而重置 | 派生是纯函数，同快照必然同结果 |
