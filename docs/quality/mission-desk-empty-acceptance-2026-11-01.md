## 0. 先砍掉一个错误方向

路线图 §P4 列了「更多办公室交互物件（会议桌 / 资料架 / 成果区）」。
但 `docs/design/office-interaction.md` 已经逐条判过：

| 物件 | 设计结论 | 理由 |
|---|---|---|
| 会议桌 | **不做** | 没有"会议"这个事实源 |
| 资料架 | **不做** | 没有知识库事实源 |
| 成果区 | **不做物件** | 会与工作坞重复 |

**照路线图做会议桌会造出装饰性谎言**，违反 `product-principles.md`「UI 不编造状态」。

所以 P4 的真实优先级是：**空状态 > 错误粒度 > 反馈**。
"更多物件"不在列表里——还没有用户抱怨缺物件。

## 1. 空状态不是"占位文案"

用户放弃一个工具通常发生在三个时刻，第一个就是
**"第一次打开，不知道从哪开始"**。

修复前，新用户第一屏看到的是：

```
边界：未声明边界。
决策（含理由）：还没有记录决策。
未决问题：没有未决问题。
工作流：还没有工作流。
产物：还没有登记产物。
```

**五个"还没有"**——准确，但**不告诉你下一步做什么**。

## 2. 设计原则

| ❌ 错的做法 | ✅ 对的做法 |
|---|---|
| 显示"暂无数据" | **告诉用户下一步做什么** |
| 一次显示所有提示 | **只提示最关键的那一个动作** |
| 用虚构数据填充 | **保持空白，但给出路标** |

## 3. 修了什么

**左侧列表（零 Mission）**
```
从这里开始
一个 Mission 就是一件你想让 AI 团队做成的事。给它一个标题和目标，
之后所有会话、决策、产物都挂在它下面 —— 关掉再打开也不会丢。
[创建第一个 Mission]
```
一条主线、一个按钮、一句人话解释"这是什么"。

**右侧详情区**：原来只有一句「选择一个 Mission 查看详情」——
但如果**一个都没有**，这个指令无解。现在分两种情况：
- 零 Mission → 「还没有选中任何 Mission」+「先在左边创建你的第一个」
- 有 Mission 但没选 → 「选择一个 Mission」+「从左侧列表点一个，能看到目标、决策、工作流和产物」

## 4. 错误提示：人话 + code

修复前 7 处重复的错误处理：
```js
'失败：' + ((r && (r.reason || r.code)) || '未知错误')
```

统一成 `explainFailure(r)`：

| 输入 | 输出 |
|---|---|
| `{code:'DELIVERABLE_INVALID'}` | `产物路径不对（文件不存在，或不在工作区里）（DELIVERABLE_INVALID）` |
| `{code:'SOME_NEW_CODE'}` | `操作失败（SOME_NEW_CODE）` |
| `{}` | `操作失败，请重试` |

**关键：永远保留 code**——那是排查的唯一线索。
格式是「人话（代码）」，不是二选一。

## 5. 为什么离线测试不够

离线能证明源码里有"创建第一个 Mission"这句话。它证明不了：
- 那句话**渲染出来了吗**（可能在 `display:none` 容器里）
- 按钮**能点吗**（可能被盖住）
- 点了**真的会打开新建表单吗**（复用已有按钮的选择器可能找不到）

第一版 PR 里如果只写文案不验证点击，很可能按钮是个死的。

## 7. 一个测试盲区的修正

变异验证时，我故意让 `explainFailure` 丢掉 code，**测试没红**。

原因：断言只检查了「代码里出现过 `${code}`」——那只证明某个分支有，
不证明**所有分支**都有。

修正：改成**真跑一遍函数**，检查四种输入（有映射 / 无映射 / 只有 reason / 什么都没有）。
重做变异 → 1 项红。

这是本轮第二个"测试自己骗自己"的案例（上一轮是断言范围没覆盖调用点之后）。
