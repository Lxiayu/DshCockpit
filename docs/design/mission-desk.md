# Mission Desk 设计（用户与团队的主交互面）

> 状态：**设计阶段（2026-11-01）** · 未实现 · P2 阶段
> 上游：`docs/product/user-journeys.md` §4、`docs/architecture/domain-model.md`、`docs/architecture/mission-core.md`
> 纪律：**这不是聊天窗口。** 右栏/主面板不做与官方 Harness UI 竞争的通用对话界面（`docs/adr/ADR-0001`）。

## 0. 一句话

> **Mission Desk 回答一个问题：这个项目现在怎么样了，需要我做什么？**

它不回答"帮我写代码"（那是官方 Harness UI 的职责）。

## 1. 为什么需要它（第一性原理）

### 1.1 用户打开应用时的真实问题排序

| 优先级 | 问题 | 现有产品如何回答 |
|---|---|---|
| 1 | 团队现在在干什么 / 卡在哪？ | 大多只显示"正在运行" |
| 2 | **需要我做什么决定？** | 常被埋在通知里 |
| 3 | 这个项目进展到哪了？ | 需要翻历史 |
| 4 | **上次我停在哪？** | **几乎没有产品回答这个** |
| 5 | 产出了什么？ | 散落各处 |

**第 4 问是我们唯一真正的差异化**，也是 Mission Core 存在的理由。

### 1.2 为什么不能做成聊天窗口

| 理由 | 说明 |
|---|---|
| 与官方正面对撞 | 官方 Harness UI 有最好的聊天/工具/审批体验（ADR-0001） |
| 聊天是线性的，项目是网状的 | 一个项目有 3 条工作流、7 条决策、2 个待答问题，聊天记录无法表达 |
| 聊天不持久 | Session 结束就断了，正是我们要解决的问题 |

## 3. 每个区块的规格

### 3.1 ① 需要你（Human Inbox）

| 属性 | 规格 |
|---|---|
| **数据来源** | Harness `$events` waterfall（approval / question）— **只读 + 转发用户决定** |
| **排序** | 危险度降序 → 时间升序（**不是时间顺序**，安全优先） |
| **显示条件** | 有 pending 才显示整块；无 pending 时**完全隐藏**（不显示"暂无待办"） |
| **操作** | 就地处理，不跳转 |
| **危险操作** | 必须展开显示真实命令原文；**无"总是允许"**（沿用现有 `office` 高危审批设计） |
| **处理后** | 立即消失（真实状态，不是动画） |
| **断线时** | 标 `stale`，保留最后已知项，不清空 |

**与现有代码的关系**：现有右栏已有"待你处理"（`docs/architecture/2026-09-23-office-right-panel-spec.md` §3 区块 3）与 `pending-mirror.js`。Mission Desk **复用**它，不重复建设。

### 3.2 ② 现在在做什么

| 属性 | 规格 |
|---|---|
| **数据来源** | Harness team roster（`running`/`inactive`）+ session 事件 |
| **显示** | `{成员} 正在 {活动短语}` |
| **活动短语** | 复用 `src/office/runtime/tool-phrases.js` 的中文短语表（已有） |
| **隐私** | 只显示工具名转短语 + 路径末两级；**不显示**参数原文 |
| **无活动时** | 显示"空闲 · 上次活动 {相对时间}"（**真实**，不编造） |
| **断线时** | 标 `stale` |

### 3.3 ③ 项目进展

| 属性 | 规格 |
|---|---|
| **数据来源** | Mission workstreams（本地）+ 派生状态 |
| **进度条** | **不伪造百分比**。如果无法从真实任务计数得出，显示状态而非进度条 |
| **计数** | 已定决策 / 待答问题 / 产物 / 会话数（全部来自 Mission 存储） |
| **点击工作流** | 展开该工作流的 session 历史与产物 |

**关键约束**：进度百分比必须有可解释的来源。若 workstream 只有"done/active/blocked"三态，就显示三态，**不要编一个 60%**。

### 3.4 ④ 上次你停在这里（**核心差异化**）

| 属性 | 规格 |
|---|---|
| **数据来源** | Mission `lastSessionSummary`（用户或 Agent 在会话结束时写入，用户可编辑） |
| **内容** | 一句话：上次做到哪、下一步是什么 |
| **时间** | 相对时间（"3 天前"） |
| **操作** | "继续这个工作流" → 创建新 session 并注入 Mission Brief |
| **首次使用** | 隐藏（不显示"还没有记录"） |

**为什么这是最重要的区块**：它直接回答用户最痛的问题——"上次我停在哪"。**没有任何现有产品回答这个。**

### 3.5 ⑤ 产物

| 属性 | 规格 |
|---|---|
| **数据来源** | Mission deliverable 索引 + 文件 digest 校验 |
| **显示** | 标题 · 验证状态（✅ 已验证 / ⚠️ 未验证 / ❌ 校验失败） |
| **操作** | 打开（系统默认应用）/ 在文件夹显示 / 复制路径 |
| **校验失败** | **明确显示**"文件已变更或丢失"，不静默 |
| **不做** | 不做内置编辑器（重复造轮子） |

### 3.6 ⑥ 项目共识（折叠）

| 属性 | 规格 |
|---|---|
| **数据来源** | Mission Shared Context（Decision / Finding / Assumption / OpenQuestion / Evidence） |
| **默认折叠** | 避免信息过载；展开后按类型分组 |
| **关键规则** | Agent 只能"提议"决策，用户确认后才 `accepted` |
| **假设** | 显示过期时间；过期标灰提示重新验证 |

## 4. 关键交互

| 交互 | 行为 | 为什么 |
|---|---|---|
| 点"需要你"的卡片 | 就地展开 + 批准/拒绝 | 不给跳转成本 |
| 点成员 | 切到办公室并聚焦该员工 | 空间化理解（复用现有 `shell:office-focus`） |
| 点产物 | 系统默认应用打开 | 不自建编辑器 |
| 断线 | 顶部细条 + 数据标灰（**不消失**） | 不制造"数据消失"恐慌 |
| `Ctrl+K` | 全局搜索（Mission/产物/会话） | 复用现有 search |

## 5. 状态渲染规则（反伪造）

| 数据状态 | 渲染 | 禁止 |
|---|---|---|
| Mission 元信息 | 总是 fresh | — |
| Harness 派生（roster/pending/changes） | 带 `observedAtMs`；超时标 `stale` | ❌ 用旧数据冒充实时 |
| 产物 digest 校验失败 | 明确标红 | ❌ 静默显示为正常 |
| 无数据 | 隐藏该区块 | ❌ 显示占位符或"暂无" |
| 断线 | 保留 + 标 stale | ❌ 清空或编造 |

## 6. 布局与尺寸

| 断点 | 布局 |
|---|---|
| 宽（≥1200px） | 两栏：左 Mission 概况，右 需要你 + 产物 |
| 中（800–1200） | 单栏纵向（上述 ①–⑥ 顺序） |
| 窄（<800） | 单栏 + 区块折叠，① 需要你 始终置顶 |

**不做响应式复杂布局**：P2 只做中/宽两档，窄档靠窗口最小宽度限制。

## 7. 与办公室的关系

```
┌─────────────┐        点击物件        ┌──────────────┐
│  办公室      │ ───────────────────▶  │ Mission Desk │
│  (空间隐喻)  │ ◀───────────────────  │  (信息密度)   │
└─────────────┘    点成员→聚焦工位      └──────────────┘
```

| 办公室擅长 | Mission Desk 擅长 |
|---|---|
| "团队整体状态"一眼看懂 | 具体数据、决策、产物 |
| 情绪/氛围 | 精确操作 |
| 发现"有人需要我" | 处理"需要我什么" |

**两者不重复**：办公室不做数据表格，Desk 不做空间呈现。

## 8. 明确不做（反模式）

| 不做 | 理由 |
|---|---|
| 聊天输入框 | 与官方正面对撞（ADR-0001） |
| 完整任务列表 | 官方 Team 任务板已有；只显示计数 |
| 成员详情面板 | 现有办公室悬停卡已覆盖 |
| 内置代码编辑器 / diff 查看器 | 官方 UI 做得更好 |
| 装饰性图表（无数据来源的"活跃度曲线"） | 违反反伪造原则 |
| 自动"完成"判定 | 用户必须显式确认 |
| "总是允许"按钮 | 安全风险 |

## 10. 验收标准（P2）

- [ ] 打开 Mission Desk，3 秒内能回答"现在在做什么 + 需要我做什么"
- [ ] 有 pending 时置顶显示；无 pending 时整块隐藏
- [ ] 危险操作展开显示真实命令；无"总是允许"
- [ ] 处理后卡片立即消失（真实状态）
- [ ] "上次你停在这里"显示真实记录；首次使用时隐藏
- [ ] 断线时数据标 stale 但不消失
- [ ] 产物 digest 校验失败时明确标红
- [ ] 无任何装饰性区块（每个区块都有数据源 + 验收标准）
- [ ] 点击成员能切到办公室并聚焦
