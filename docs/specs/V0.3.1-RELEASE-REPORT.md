## 1. 项目现状概览

### 1.1 项目定位

DshCockpit 不是给 `dsh` 再套一个窗口——而是一个**桌面控制平面**。它把 DeepSeek Harness 从终端命令变成常驻桌面的 Agent 服务，提供更新、成本、后台任务、数据安全、手机遥控的完整桌面产品体验。

### 1.2 已交付能力（截至 v0.3.0）

| 能力 | 状态 | 护城河深度 |

| 运行时/壳双层自动更新 + 冒烟守卫 | ✅ | 坏版本不激活（最硬护城河，无人能抄） |
| Token 监控 + 成本中心 + 预算报警 | ✅ | 按工作区归因、峰谷分时、80%/100% 报警 |

## 2. Git 历史与版本演进分析

### 2.1 版本演进脉络

```
v0.1.x ──→ v0.2.x ──→ v0.2.8 ──→ v0.2.9 ──→ v0.3.0
原型期      功能期      加固期      冲刺期      控制平面大版本
```

最近 40 次提交分析（从 `553b316` 到 `2e94e18`）：

| 阶段 | 提交范围 | 特征 |
|---|---|---|
| **v0.3.0 发版** | `553b316` | 版本号 + Release Notes 收尾 |
| **IM 渠道重构批** | `70706e6` → `3549023` | 飞书协议修正、双向会话控制、体验层 |
| **修复批** | `fcd68eb` → `81c89d6` | Keychain 免密、Rail 对齐、E2E 门禁 |
| **核心功能批** | `711676a` → `0ecc13f` | 自动更新、缓存看板、周报、通知中心 |
| **架构拆分批** | `379352b` → `a862150` | 主进程模块化（window-manager/aux-windows/tray-menu/runtime-supervisor） |
| **分发准备批** | `c70569d` → `2e94e18` | NSIS 主轨、slim 轨道、产物门禁 |

### 2.2 关键发现

1. **迭代速度极快**：v0.2.8 → v0.2.9 → v0.3.0 在 3 天内完成，平均每天 10+ 次提交
2. **架构质量持续提升**：A1 系列提交（step1-step6）系统性地重构了 main.js 模块化
3. **测试先行**：多次提交先加测试再修代码（`cc62dd1` 对齐 mock、`421137a` 修复构建）
4. **修复密度高**：约 40% 的提交是 fix/refactor 类型，工程纪律严格
5. **无 Linux 提交**：整个 git 历史中没有 Linux 相关改动

## 3. 竞品深度调研

### 3.1 竞品全景图谱

调研了 DSH 桌面端赛道所有主要参与者，按 stars 排序：

| 项目 | Stars | 技术栈 | 特征 |
|---|---|---|---|
| **anywhere-labs/dsh-desktop** | **~21.2k** | Electron + Cordis | 万物皆插件，30 贡献者，12,688 commits |
| **dataelement/dsh-desktop** | ~2.7k | Electron | 企业级背景（bisheng 团队） |
| **hairyf/deepseek-harness-desktop** | ~1.3k | **Tauri** | 5MB 安装包，三平台 |
| **DSH TUI (ccch1mneyyy)** | ~2.6k | Terminal | TUI 风格 |
| **CSlawyer1985/dsh-desktop** | ~1k | Electron | 简洁封装，有官网落地页 |
| **formycity/dsh-desktop** | <100 | **Tauri** | 轻量启动壳，不内置运行时 |
| **DshCockpit（我们）** | **—** | **Electron** | **控制平面，最深护城河** |

### 3.2 头号竞品：anywhere-labs/dsh-desktop（~21.2k stars）

**背景**：由 Anywhere Labs 团队维护，DSH 生态中最大的桌面项目。DSH 发布当天（8月13日）即创建，10 天达 13.8k stars。

**已交付强项**：
- **插件市场（DSH Community Market）**：内置、可搜索、一键安装——我们只有"浏览 GitHub 话题"
- **Profile 管理**：兼容/高级双模式，UI 化切换——我们没有
- **内置终端**：私有 shim 不污染系统 PATH——我们明确不做（铁律 1）
- **macOS 签名公证**：v2.0.0 已完成——我们暂缓（D-1）
- **Mica 窗口效果**：Windows 11 视觉效果——我们没有
- **自建更新服务器 + 官网 CDN**：dshdesktop.cn——我们没有
- **30 贡献者 / 12,688 commits**：社区规模碾压——我们单人维护
- **飞书文档站**：完善的文档体系——我们只有 GitHub Markdown
- **手机原生客户端**：iOS/Android 原生 App——我们是 Web 响应式

**结构性裂缝（我们的机会）**：

| 问题模式 | 证据 | 根因 |
|---|---|---|
| 插件装不上/装了崩 | #351 #346 #341 等 | "万物皆插件"的代价 |
| 插件冲突导致启动即闪退 | #325 | 插件跑在宿主进程 |
| 上游破坏性更新毁 profile | v2.0.2 官方公告 | submodule pin 架构的原罪 |
| Windows 持续闪退/白屏 | #347 #326 #321 等 | 复杂架构的代价 |
| 连"托盘重启"都是用户求的功能 | #335 | 基础功能缺失 |

**战略含义**：21k stars 背后有大量踩坑用户，是转化成本最低的受众。"从 DSH Desktop 迁移指南"是有真实需求的内容。

### 3.3 二号竞品：dataelement/dsh-desktop（~2.7k stars）

**背景**：dataelement 团队（也维护 bisheng 12k stars），企业级 AI 平台背景。

**特征**：
- 独立配置目录（不共享官方 `~/.dsh`）——双刃剑（隔离性好但配置不通用）
- 企业级工程背景（团队有成熟开源项目经验）
- 仍在快速增长中

### 3.4 值得关注的竞品：hairyf/deepseek-harness-desktop（Tauri，~1.3k stars）

**特征**：
- **Tauri 技术栈**：安装包仅 5MB（vs Electron 的 ~100MB+）
- 三平台支持（Windows/macOS/Linux）
- 首次启动引导 + 预设插件
- 开发/生产环境隔离

**威胁**：Tauri 的轻量优势正在吸引更多用户。如果 Rust 生态成熟，Tauri 桌面壳可能成为主流选择。

### 3.5 竞品趋势总结

1. **DSH 桌面赛道已分化为三层**：
   - 第一层：anywhere-labs（21k stars，头部通吃）
   - 第二层：dataelement（2.7k）、hairyf（1.3k）、我们
   - 第三层：大量 <1k stars 的项目

2. **差异化方向验证**：头部项目裂缝清晰，我们的"可靠性即产品"策略完全正确

3. **Tauri 威胁上升**：轻量安装包 + Linux 支持 + 三平台，是后发优势

4. **插件层复刻预警**：dsh-web-ui（5.2k stars）已含插件级 live token stats 和 mobile remote UI——我们的护城河必须下沉到插件层做不了的深度

### 4.2 核心差距分析

#### 差距 1：社区与生态（最大差距）
- **21k vs 未知**：star 差距是数量级的
- **30 贡献者 vs 1**：团队规模差距意味着迭代速度和问题响应速度的差距
- **12,688 commits vs ~300**：工程投入量的差距
- **本质原因**：我们起步晚（DSH 8月13日发布，我们同期起步），且单人维护

#### 差距 2：插件生态
- 头部项目有**内置插件市场**（DSH Community Market），可搜索、一键安装、分类浏览
- 我们只有"浏览 GitHub dsh-plugin 话题"的基本集成
- **但是**：头部项目的插件生态也是其最大痛点（插件冲突、启动崩溃）

#### 差距 3：基础体验
- 签名：我们未签名（xattr 手动放行），头部已完成
- 终端：头部有内置终端（我们明确不做）
- Profile 管理：头部有双模式切换（我们没有）
- 视觉效果：头部有 Mica（我们没有）
- 官网：头部有 dshdesktop.cn（我们的 website/ 未上线）

#### 差距 4：技术水平
- Tauri 竞品安装包仅 5MB，我们 ~90MB
- 这对下载转化率和磁盘占用有直接影响

### 4.3 我们的核心优势（护城河）

1. **运行时更新 + 冒烟守卫**：坏版本不激活，这是最硬核的能力，竞品无人能做到
2. **成本控制深度**：按工作区归因、峰谷分时、预算报警、缓存经济学——插件层复刻不了
3. **启动自检 + 兼容快报**：可靠性即产品，直接打竞品 "装不上/启动崩" 的痛点
4. **IM 渠道双向控制**：飞书/企微/钉钉 ↔ Harness 会话双向操控，竞品没有
5. **工程纪律**：376 项测试全绿、E2E 产物门禁、C-7 语法检查——这些是可持续质量的保证

## 5. v0.3.1 开发建议

### 5.1 版本号决策

**建议：v0.3.1**（过渡版本，非产品形态级升级）

理由：
- [PREDEV-FEATURES-REPORT.md](file:///Users/xia/program/dsh/DshCockpit/docs/specs/PREDEV-FEATURES-REPORT.md) 的 S1（壳容器化 + 办公室视图）范围较大，且风险登记为"高"
- 建议先完成 T1/T2/T3 三个过渡项作为 v0.3.1，S1 作为 v0.4.0
- 这样可以在 1-2 周内发布一个没有高风险重构的过渡版本，积累用户反馈

### 5.2 开发范围优先级

#### P0（本版必做）

**T3 · GitHub Pages 落地页**（工作量：小，影响：大）

- **为什么是 P0**：在竞品调研中，头部项目有官网，我们没有。没有落地页意味着：
  - 搜索引擎不可发现
  - 无法展示产品截图和对比表
  - 下载入口不直观
- **做什么**：复用 `website/` Vite 工程，上线 Hero + 三支柱（更新/成本/后台）+ 对比表 + 兼容快报入口 + 下载直达 Releases
- **验收**：可从 GitHub Pages 访问，下载按钮直达最新 Release

**T1 · MCP 管理器 MVP**（工作量：中，影响：大）

- **为什么是 P0**：MCP 已成"AI 的 USB-C"，40+ provider 用户都需要。壳级 MCP 管理器目前无人做，是空位。这是**差异化传播钩子**。
- **做什么**：先 T-0 勘察（dsh 的 MCP 配置面）→ 通过后设置页新增「MCP」子页：已装列表、registry 搜索添加、连接测试、启用禁用
- **验收**：添加 ≥2 个真实 MCP Server 并连通一次

**T2 · 插件健康度面板**（工作量：小，影响：中）

- **为什么是 P0**：直接打竞品 #325 类事故（插件冲突致启动闪退）的信任缺口。定位"插件混乱中的稳定器"。
- **做什么**：读取 profile 已装插件清单，与内置已知冲突特征库比对，给出状态与预警
- **验收**：已装插件列表 + 冲突预警正确

#### P1（高价值，资源有余再做）

**签名与公证重启评估**

- 虽然 ROADMAP D-1 说等到 500 stars 或 2000 月下载，但调研发现：
  - **macOS 签名是转化杀手**：xattr 指令每多一步，用户流失率就高一分
  - 竞品已完成签名，这直接影响了用户的第一印象
- **建议**：重新评估 D-1 条件。即使是 ad-hoc 签名（已做完实验，见 `12c084f`），也比完全无签名好

#### P2（本版不做，延后到 v0.4.0）

**S1 · 壳容器化 + 办公室视图**

- 产品形态级升级，适合 v0.4.0
- 风险高（iframe 嵌入、Edge Rail 注入兼容性）
- 建议先完成 T1/T2/T3 积累用户基础，再做大版本

### 5.3 版本节奏建议

```
Week 1 (8/29 - 9/4):  T3 落地页 + T1 MCP 勘察
Week 2 (9/5 - 9/11):  T1 MCP 实现 + T2 插件健康度
Week 3 (9/12 - 9/14): 回归测试 + 发版
```

### 5.4 与竞品差距的闭环策略

| 差距 | 策略 | 时间线 |
|---|---|---|
| Star 数差距 | 不正面追赶。通过"可靠性即产品"内容输出（Show HN/Reddit），承接竞品踩坑用户 | 持续 |
| 插件生态 | 从"浏览话题"升级为"内置市场"有计划，但本版先做插件健康度面板（T2）作为信任锚点 | v0.3.1 |
| 签名公证 | 重新评估 D-1 条件，优先 mac notarization | v0.4.0 前提 |
| 官网落地页 | 本版直接上线（T3） | **v0.3.1** |
| Linux 支持 | 跟踪 Tauri 路线，暂不投入 | 远期 |
| 贡献者 | 通过落地页 + 清晰 CONTRIBUTING 吸引 | 持续 |
